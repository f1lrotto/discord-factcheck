Sixteen rounds of finding the sharp edges.

A complete round-by-round account of the correctness, privacy, accounting, prompt injection, output-safety, lifecycle, deployment, and test-coverage issues found while hardening the Discord bot. Rounds 1–15 were remediated before the next review. Round 16 is known but intentionally not applied.

Money, lifecycle, citations, and first parser defenses

Round 1
  1. Incomplete or non-finite provider cost could settle at zero instead of charging the conservative reservation.
  2. Two-stage inference lacked one overall deadline; leases and conversation locks were not safely bounded/tokenized.
  3. Mongo transactions used unsupported parallel operations; settings races/recovery and partial client initialization needed deterministic handling.
  4. Shutdown could close Mongo with unresolved settlements instead of retrying and refusing unsafe closure.
  5. SSE reads/frames could materialize unbounded data rather than incremental bounded parsing.
  6. Output links were not restricted to exact public research sources; unsafe/private/bare/invented links, incomplete streams, and stale Discord chunks needed controls.
  7. Pre-inference Discord work needed cancellation/bounds and unrelated/rejected traffic containment.
  8. Application logs could serialize arbitrary third-party errors instead of an allowlist.
  9. Production Mongo URI options could disable transport security; Railway examples were ambiguous.
  10. Privacy docs did not clearly say transcript content remains plaintext even when identifiers are pseudonymous.
  11. Coverage gaps remained for missing usage, overall abort, SSE/output bounds, links, shutdown, races/recovery, bilingual injection, live red-team behavior, and sensitive per-file floors.

  1. Only structured OpenRouter url_citation annotations—not model prose—could authorize sources.
  2. The URL filter missed fuzzy/IDN domains, email, Markdown destinations, and uncommon/one-character schemes.
  3. Mongo selection/connect/socket/operation timeouts and Discord handler draining were incomplete.
  4. Expired in-memory rate-gate keys could poison the capacity ceiling.
  5. The cost envelope used an assumed token ratio instead of the actual bounded research-response size.
  6. Tests were missing for settlement races, time boundaries, nonnegative reservations, persisted collections, DB continuations, rate capacity, Mongo timeout config, and handler drain.
  7. The paid English/Slovak × both-model injection matrix remained an external gated release check.

  1. DeepSeek V4 Flash reasoning metadata was stale: it needed low/high/max, default high, and no xhigh.
  2. Discord rendering needed serialization, cancellation, and continued tracking after caller timeout.
  3. Reservation recovery needed bounded batches, single-flight ticks, and shutdown coordination.
  4. Slash commands needed immediate ephemeral acknowledgement before Atlas work.
  5. Citation annotation count and URL length needed bounds during SSE ingestion.
  6. Escaped code delimiters and predictable fragment placeholders could bypass link sanitization.
  7. Non-finite/negative/unsafe provider usage could poison Mongo accounting instead of conservative fallback.
  8. The paid release gate needed one command covering both models, languages, reasoning efforts, web, injection, and misuse refusals.
  9. Extreme spend-limit values could overflow dollar-to-microdollar conversion and disable limits.
  10. A failed recovery sweep still had to drain and log safely without blocking Mongo close.

Round 4
  1. The paid release command did not fail closed early enough when the capped key or explicit flags were absent.
  2. Paid injection assertions could accept trivial language-neutral output or refusal preambles followed by harmful instructions.
  3. Recovery tests did not prove the 100-request boundary, single-flight overlap, shutdown waiting, and safe failure logging.
  4. Discord interaction mocks did not accurately model defer/edit state or real operation timeouts.
  5. Mentions, emoji, message links, and Discord snowflakes could survive inside prompts/transcripts.
  6. A malformed later SSE usage event did not necessarily invalidate an earlier apparently valid event.
  7. Public research could receive scheme-less localhost, private IP, host-port, internal path, or Discord-message targets.
  8. Unknown-scheme removal also destroyed ordinary English/Slovak labels such as Note: and Poznámka:.

Round 5
  1. Any malformed nonempty SSE data frame after valid usage needed to invalidate usage and force conservative settlement.
  2. Private-target detection missed Unicode/NFKC dot variants, unbracketed private IPv6, and single-label intranet host+port/path forms.
  3. CommonMark angle autolinks needed scheme-aware removal without deleting ordinary emphasized labels.
  4. Both models needed the shared supported output parameter max_tokens, not a Luna-specific spelling.
  5. Paid red-team evaluators relied on brittle word lists rather than unit-tested normalized correctness/refusal semantics.
  6. The failed-recovery test could pass without exercising production client-close orchestration.

  8. The unprivileged privacy command needed stateful defer/edit assertions.
